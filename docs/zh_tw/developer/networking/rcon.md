# RCON（遠端控制台）

## 什麼是 RCON

RCON（Remote Console，遠端控制台）是由 Valve 設計的協定，允許管理員遠端控制和管理遊戲伺服器。它提供了一種從不同位置（例如手機或另一台電腦）在伺服器上執行指令的方式。

## 為什麼使用 RCON

- **便利性：** 只要有網路連線，即可從任何地方管理您的伺服器。
- **彈性：** 無需親臨伺服器所在地即可執行指令。
- **效率：** 自動化任務並簡化伺服器管理流程。

## SSH 與 RCON

### SSH

- 提供強大的加密功能，保護用戶端與伺服器之間傳輸的資料。
- 主要設計用於安全的遠端登入以及在遠端機器上執行指令。
- 常用於管理 Linux/Unix 系統、設定網路以及執行腳本。
- 提供類似 shell 的環境，讓您能夠執行各種指令並與遠端系統互動。

### RCON

- 專為遊戲伺服器的遠端管理而設計，允許您控制和管理伺服器的設定與操作。
- 通常不如 SSH 安全，因為它通常依賴明文密碼。
- 主要由遊戲伺服器管理員用來管理遊戲伺服器。
- 僅具有一組有限的遊戲專用指令。

## 封包

RCON 是一個非常簡單的協定，僅有少數幾種封包。以下是 RCON 封包的結構：

| 欄位 | 說明 |
| --- | --- |
| ID | 用於表示驗證失敗或成功 |
| Type | 識別封包類型 |
| Body | 訊息（字串），例如指令或密碼 |

### 伺服器接收封包 <sub><sub>（用戶端 → 伺服器）</sub></sub>

| Type | Packet |
| --- | --- |
| 2 | Auth |
| 3 | ExecCommand |

### 用戶端接收封包 <sub><sub>（伺服器 → 用戶端）</sub></sub>

| Type | Packet |
| --- | --- |
| 2 | AuthResponse |
| 0 | Output |

## RCON 運作方式

**驗證：**
1. RCON 用戶端傳送包含指定密碼的驗證封包。
2. 伺服器驗證密碼並回應驗證回應封包。
3. 若成功，回應封包會包含與用戶端傳送相同的 ID。若失敗，ID 為 -1。

**指令執行：**
1. 已驗證的用戶端現在可以傳送指令執行封包，每個封包包含要執行的指令。
2. 伺服器處理指令並回傳包含結果或任何錯誤訊息的輸出封包。
